Template Studio Test Cases

116 test cases in plain words for building vendor-onboarding templates from the console: the list, the type picker, sections, the 8 field types and their settings, conditional logic, preview, save, the saved template on the real vendor form, Generate with AI, and the buyer form. "Expected" is what the code does today; where product may want something else, the case says so.

How the feature works

Where it is

Admin console (Controls page) → card 'Manage Templates' → /template-studio. Routes are permission-gated: list needs template:read_record, create template:create_record, edit template:update_record (same keys the backend policy checks on POST/PATCH/DELETE /templates).

What it manages

Only four template kinds: Vendor Onboarding (template_for rfi + vendor_onboarding), Vendor Onboarding — Buyer Form (vendor_onboarding_buyer_form), Purchase Order, RFQ/Auction. The list hides every other template kind.

Vendor Onboarding editor

Sections (tabs) → fields → settings. 8 field types: Short Text, Long Text, Number, Date, Dropdown, Multi Select, Radio, Attachment. Common settings: Label, Key (auto from label, unique, editable), Type, Visibility (Editable / Read-only / Hidden), Required, Helper text. Extra settings depend on the type: Format mask (regex, typing aid only), Validations (External: PAN, GST, MSME, Bank [2 inputs], CIN, FSSAI, TAN, VAT, with response rules; Internal: Regex, Must equal, Reject duplicate, Contains), Block paste, Prefill on load (6 allowed sources), Autofill after validation, Write back to a record (Company.misc), Options (stable ids), Data source (+ cascade, {{field}} placeholders), Populate on select, Reset fields on change, Allowed file type.

Logic tab

Rules: When <field> <is | is not | is empty | is not empty | contains> <value> → effects Show / Hide / Make required / Make optional on other fields. Values of option fields are compared by option id, so renaming an option keeps the rule. Conflicts are warned (last rule wins). Saved as configurations.conditional_block; one Hide = 3 action rows (hidden, not required, value cleared).

Preview tab

Live form: sections, labels, *, helper text, controls; rules run as you fill; nothing is saved or called.

Save

Studio checks: name, ≥1 section, ≥1 field, every field has label and key, no duplicate keys, no rule/field pointing at a missing key. Then POST/PATCH /templates with forms[] (fields in page_response_headers) + configurations. Backend checks each form has order, name, config.type and a non-empty field list, each widget has key_attribute, name, configuration.field_type — else 422 'Invalid Form'. No name-uniqueness rule.

Buyer Form editor

One field list pre-filled with 13 standard buyer fields (default = fixed key, custom = key editable, '_custom' suffix). Types: Text, Number, Date, Dropdown (data source), Formula ({Field} tokens). No sections, no logic, no validations. Saved as widgets.global_price_components.

Generate with AI

Vendor Onboarding only: upload PDF/JPG/Excel ≤10 MB → POST /ask_ai_chats/vendor_onboarding_template_draft → poll /external_requests/<uuid> → draft opens in the editor. On the backend branches read for this sheet the route does not exist yet — verify on the test environment.

Watch-outs found in the code

1) An extra section with no fields passes the studio but is refused by the backend ('Invalid Form'). 2) On a workspace with vendor onboarding v3 the backend expects fields in page_headers; the studio sends them in page_response_headers → edits may fail. 3) Bank validation can be saved with the IFSC input unmapped. 4) A key typed by hand is not cleaned (spaces/capitals allowed). 5) The 'Fields' column shows '-' for vendor onboarding templates. 6) No unsaved-changes warning, no autosave. 7) Incomplete rules are dropped silently on save. 8) Read-only fields look editable in Preview.
