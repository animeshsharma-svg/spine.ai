D__002 OPEN — P1 NO BE — All users PO expense_period_end_date before start date is accepted confirmed · POST /api/fx_responses/create_row · procol_sandbox_demo
what we found · how to reproduce The schema itself declares the rule end_date >= start_date, and the platform ignores it — the record is created with 200. A rule the schema publishes but does not enforce is worse than no rule, because callers trust it. Repro: [negative] expense_period_end_date rejects a value before expense_period_start_date
D__003 OPEN — P1 NO BE — All users PO mandatory currency can be omitted through the API confirmed · POST /api/fx_responses/create_row · procol_sandbox_demo
what we found · how to reproduce currency is mandatory in the schema and cannot be cleared in the UI, which defaults it to INR. The API accepts a create with it absent. A UI/API divergence: the API permits a document the UI cannot produce. Repro: rejects a create that omits a mandatory field

Confirmed against the live schema, so it is tenant configuration rather than stale local config. Needs tenant admin to fix. Repro: tier 1 + tier 2 'relation fields name a resolvable target' (quarantined as a known issue)
tenant configuration, not code — quarantined in tier 2 so it does not mask new drift

fix is master data, not the field

D__009 TO BE DISCUSSED — P1 NO BE — All users Approvals omitting app-version silently returns a reduced payload confirmed · GET /api/fx_responses/{uuid}/get_approvals · both
what we found · how to reproduce The platform selects a response serializer from the app-version header. With no such header it answers 200 but strips every step and approver uuid, so a document cannot be approved and the cause is invisible — the call looks successful. Same effect on the approval-flows list, which switches between numeric ids and encoded uuids. The suite now always sends app-version. Repro: measured: no header -> approver.uuid undefined; 9.4.349 -> uuid present
worked around in the suite by always sending app-version — decide whether the default should be the full payload
