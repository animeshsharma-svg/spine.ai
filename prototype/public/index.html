Principles

The rules it keeps on every run.

What spine.ai will and will not do, whichever client it is testing.

  • Human in the loop

    A not-checked result always says why and never counts as a pass. You decide what is a bug, on the sheet your team already uses.

  • Each client as it is set up

    It reads the client's own configuration first, so a case expects what that client's settings allow.

  • Rules decide, not AI

    AI plans the steps. The verdict is a fixed comparison of what was expected with what Procol replied.

  • Proof you can act on

    Every broken result carries expected next to actual and the request that reproduces it.

  • Safe by design

    UAT and sandbox only, QA test vendors only, and a read-only database. Live data is never touched.

Verdicts

Three words. No AI verdicts.

Fixed rules compare what the case expected with what Procol replied. A not-checked result always says why, and never counts as a pass.

Worked

Procol did what the case expected.

POST /event_groups → 200A draft with valid line items is created.

Broken

It did something else. Expected and actual, side by side.

POST /event_groups → 500Malformed line items should be refused. The server crashed instead.

Not checked

Always with the reason. Never counted as a pass.

PATCH …/currency_exchange_rates → 422"Request not found": the rule under test was never reached.

Straight into the bug sheet your team already uses, with the request that shows it. Then it is checked again on every run after.
